# 瘦身候选与风险

分级依据：能否只动我们自己的层（userscript / launcher / CSS），还是必须碰抖音 bundle。

## A 类：低风险（只动我们自己的代码）

| # | 候选 | 依据 | 预计收益 | 验证方式 |
|---|---|---|---|---|
| A1 | 隐藏非核心入口（已有 17-glass-nav：AI抖音/放映厅/短剧/小游戏） | 已实施并实测 `hidden=4` | DOM 少量、视觉清爽 | 已通过 |
| A2 | 页面隐藏时暂停我们自己的脚本任务 | 已放弃（该窗口 `document.hidden` 不变） | 0 | 已证伪 |
| A3 | 减少我们脚本的 DOM 查询频率（12 的 250ms unlock 已有配置守卫 + patch 幂等） | 代码审查 | CPU 小幅 | 改前后 30 秒 CPU 对比 |
| A4 | 删除启动器死代码（已做：mediaLog + request 监听） | 实测 | Node WS -21%、CPU -32% | 已通过 |

## B 类：中风险（需要逐项验证回归）

|---|---|---|---|
| B1 | 延迟加载"我的/直播"页的客户端附加脚本 | 需确认脚本支持按路由启停 | 切页时功能缺失 |
